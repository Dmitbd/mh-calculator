# Changelog

Все заметные изменения MH Calculator фиксируются в этом файле.

## Unreleased

### Added

- Добавлены эксплуатационные gates: documented raw/gzip budget production web-entry, exact Chromium E2E для initial loader, remote/fallback каталога, build view, non-admin denial и dirty edit, а также общий безопасный recovery boundary.
- Добавлена ограниченная структурированная диагностика выбора fallback и отказа non-admin без raw ошибок, payload, stack или backend credentials.
- Добавлена единая ограниченная bootstrap-проверка Supabase с детерминированным manifest версий ресурсов; каталог и экран билда читают remote hero-build данные только после совместимого ответа и независимо переходят на bundled fallback при сбое своего ресурса.
- Добавлены детерминированные bundled snapshots билдов, проверенный last-known-good cache и автоматическое обновление snapshot через отдельную ветку и pull request.

### Changed

- Административный билдер разделён на независимо тестируемые editor, auth/status, server-command, async-currentness и validation-navigation модули; пользовательский workflow, revision-защита и гонки ответов сохранены.
- Локальная разработка, pull request CI и публикация Pages используют один закреплённый Node/npm toolchain и общий gate совместимости Expo, тестов, TypeScript и чистого web export; зависимости SDK 56 приведены к рекомендованным совместимым версиям.
- Источник билдов выбирается в порядке совместимый remote, самый новый полностью проверенный last-known-good, bundled snapshot; частичный, старый, несовместимый или повреждённый набор не заменяет принятые данные.
- Критические иконки каталога и выбранного билда теперь предзагружаются ограниченным набором, ожидают свободный слот вместо ложной готовности при заполненном реестре и используют общий кешируемый контейнер с фиксированным placeholder/error-состоянием без скачка размеров.
- Первоначальная загрузка каталога, билда и административного экрана использует единый доступный loader с поддержкой reduced motion; фоновые обновления не скрывают уже показанный контент.
- Серверный билд героя теперь имеет ровно одно состояние: черновик атомарно становится опубликованным, а опубликованный билд нельзя удалить или вернуть в черновик.
- Действия удаления опубликованного билда убраны из экрана героя и административного билдера.
- Прямые записи в `hero_build_sets` закрыты; создание черновика, публикация и обновление опубликованного билда выполняются отдельными RPC с обязательной server-проверкой admin claim и исходного состояния.
- Режим редактирования опубликованного билда показывает единственное действие `Обновить` только при реальных изменениях, проверяет и отправляет полный комплект без создания черновика и скрывает действие после успешного обновления.
- Локальные изменения опубликованного билда сохраняются при переключении вкладок и ошибках обновления; уход назад, выход, смена героя и закрытие страницы теперь требуют подтверждения.
- Supabase payload билдов теперь читается как недоверенный JSON и проходит версионную доменную валидацию; невалидный remote не заменяет локальный fallback и возвращает диагностируемую причину.
- Сохранение и публикация билдов теперь используют оптимистичную проверку revision; параллельное изменение показывает отдельный конфликт и не сбрасывает локальные правки.
- Для билдов ведётся неизменяемая история авторских revisions; опубликованный снимок можно восстановить только созданием новой опубликованной revision.

### Fixed

- Production static export с настроенным Supabase больше не создаёт browser auth storage во время Node SSR; публичные env значения при этом встраиваются в browser bundle для последующей hydration.
- SSR и первый hydration-render каталога теперь начинают с одинакового loader-only состояния; fallback или remote-контент выбирается только после client effect без несовпадающей разметки.
- Возврат из общего recovery boundary восстанавливает главную даже при сбое уже на маршруте `/`; диагностический лог строится только из явного allowlist, а deployment artifact проверяется budget после export с реальными env.
- Последовательные клики по цвету пробуждения оружия больше не теряются при объединённом React update; async-переходы билдера используют единый атомарный controller без параллельных request-latches экрана.
- Каждое LKG-поколение теперь хранится одним атомарным AsyncStorage blob; все storage-операции имеют deadline, поэтому зависшее чтение выбирает bundled fallback, зависшая запись не блокирует проверенный remote и не ломает очередь следующих сохранений.
- Автоочистка LKG больше не удаляет повреждённые или недоступные generation keys без CAS; до `128` exact кандидатов проверяются, а очистка затрагивает только валидные поколения за четырьмя наиболее свежими.
- Каталог и detail теперь принимают remote только из одного полного snapshot; LKG восстанавливается из ограниченного набора immutable-поколений при повреждённом или проигравшем гонку pointer, bundled-файлы проверяются без реконструкции manifest, а SQL/workflow используют согласованный byte budget, exact branch lease и только открытый PR.
- Fresh Supabase migration chain теперь явно выдаёт `anon, authenticated` право `SELECT` на билды героев; published-only RLS продолжает скрывать черновики, а права прямой записи не открываются.
- Bootstrap manifest теперь атомарно хеширует полный ordered snapshot опубликованных метаданных одним `SECURITY INVOKER` SQL RPC через anon/RLS, не зависит от Data API pagination, строго ограничивает body по UTF-8 байтам и управляет реальными source-переходами каталога и экрана билда.
- Отмена загрузки каталога теперь немедленно завершает wrapper типизированным исходом без зависших closures или ложного fallback, а локальный Hero Build симметрично диагностирует `not-configured` ровно один раз на героя.
- Смена героя в маршруте просмотра теперь атомарно сбрасывает прежний билд и выбирает валидную вкладку вместе с новым ответом без старого контента или промежуточной пустой карточки.
- Восстановление admin-сессии в режиме редактирования больше не показывает editor до начала загрузки опубликованного билда.
- Зависший запрос каталога через `8` секунд переходит к локальному fallback и освобождает timer; событие reduced motion больше не перезаписывается устаревшим системным snapshot.
- Каталог билдов больше не показывает bundled Бастет и Морану перед выбором источника: remote-режим содержит только опубликованные backend IDs, а ошибка явно включает локальный fallback с повторной попыткой.
- После выхода из редактора опубликованного билда старая dirty-форма больше не возвращается при повторном входе; подтверждения переходов сериализованы и не продолжаются после закрытия экрана.
- Ошибка выхода из редактора больше не очищает server revision: сохранённую dirty-форму можно сразу обновить, а поздний ответ отменённого запроса не подменяет её revision.

- Полная валидация опубликованного билда теперь открывает первую проблемную вкладку, показывает ошибку у соответствующего поля и прокручивает к его секции.
- Неуспешная загрузка другого героя больше не меняет identity сохранённой формы и не оставляет последующее сохранение прежнего героя в бесконечном pending.
- Восстановление версии теперь требует историю того же героя, а все операции версий отклоняют запрос без идентификатора авторизованного администратора.
- Поздний ответ сохранения или публикации предыдущего героя больше не меняет состояние и сообщения после выбора другого героя.
- Административный билдер, черновики и изменение билдов теперь доступны только пользователям с Supabase admin claim; RLS оставляет остальным только чтение опубликованных билдов.
- Ошибка локального выхода после non-admin login больше не подменяет отказ `Недостаточно прав администратора.`.
- Runtime-проверка Supabase-билдов теперь отклоняет неполные leaf-вкладки, отсутствующий у них `gameMode`, лишние/accessor/symbol-поля, sparse/слишком глубокие или объёмные структуры и неканонические даты; непустая backend-строка без собственного `payload` считается повреждённой, проверки строк, ключей и divinity loadout ограничены budgets, а fallback сохраняет типизированную причину `invalid-data`.

### Documentation

- Правила выпуска описывают воспроизводимую установку и единый verification gate, production audit с классификацией цепочек и запрет слепого `npm audit fix --force`.
- Постоянные specs приведены к фактическим именам и формам типов export билдера, каталога мажорных скиллов, прогресса божественности и нормализованного ввода антиквариата.

## v1.1.0 - 2026-08-12

### Added

- На главном экране добавлен footer с текущей версией приложения и ссылкой «Что нового» на последний GitHub Release.
- Билдер поддерживает серверные черновики вкладок: отдельные списки героев, восстановление незавершённого комплекта и удаление черновика после публикации.

### Fixed

- Проверка иконок антиквариата приведена в соответствие с каталогом: записи с PNG проверяют изображение, записи без PNG — контролируемую заглушку.

### Documentation

- Документация объединена в четыре постоянные спецификации функций приложения.
- Добавлены каталог возможностей, правила ведения changelog, тегов и GitHub Releases.
- Временные материалы `docs/superpowers` исключены из Git.

## v1.0.0 - 2026-08-12

### Added

- Калькулятор божественности с диапазоном уровней, ручным прогрессом, автозаполнением и учётом собственных ресурсов.
- Каталог и просмотр билдов героев с фильтрами, вкладками, экипировкой, пробуждением оружия и божественностью.
- Административный билдер с вкладками, валидацией, JSON-экспортом и Supabase-публикацией.
- Калькулятор события «Антиквариат» с сохранением ввода, каскадными наградами, распределением монет и сундуками соперничества.
