# Бэклог MH Calculator

Этот документ хранит согласованные задачи, которые ещё не реализованы. Он не описывает текущее поведение приложения и не заменяет постоянные `docs/*-spec.md` или `CHANGELOG.md`.

При реализации задача переносится из backlog в соответствующий capability spec и `CHANGELOG.md` одновременно с кодом и тестами.

## Загрузка экранов и изображений

### BL-001 — Подтвердить производительность изображений на целевых runtime

**Уже реализовано.** Критические иконки каталога и выбранного героя проходят через ограниченный дедуплицированный preload, а общий `AppImage` сохраняет фиксированную геометрию, platform cache hint и контролируемые loading/error-состояния. Статический production export подтверждает пути `/mh-calculator/...`; локальный HTTP замер отделяет первую передачу от условной cache validation. Operational gate фиксирует raw/gzip entry budget и запускает production Chromium E2E, но не подменяет реальные Pages/native замеры.

**Что осталось проверить и при необходимости усилить:**

- в реальном production web-браузере на GitHub Pages измерить cold и repeat загрузку, transfer/cache behavior и отдельно decode/paint критических PNG через browser Performance API или DevTools;
- на поддерживаемых native runtime измерить cold/repeat network, memory/disk cache и decode/paint на реальном устройстве или репрезентативном эмуляторе;
- сопоставить результаты с актуальными ceilings из единственного исполняемого источника [scripts/web-bundle-budget.json](../scripts/web-bundle-budget.json) и operational E2E; если измерения покажут регрессию, скорректировать критический набор, timeout или asset format без all-catalog preload;
- сохранить доказательства с окружением, сценарием, количеством/размером URL и явным разделением transfer, cache validation и decode/paint.

**Критерии готовности:**

- есть воспроизводимые cold/repeat измерения для production GitHub Pages и каждого заявленного поддерживаемого native runtime;
- browser/native evidence отдельно описывает network transfer, cache hit/validation и decode/paint, не выводя одно из другого;
- критические иконки не появляются позже основного содержимого в пределах принятого budget, а below-fold изображения не блокируют экран;
- ошибка, offline и зависший preload сохраняют фиксированный placeholder и не удерживают readiness gate бесконечно;
- итоговые budgets и команды проверки закреплены в performance/operational gates.

Текущий bundled snapshot содержит `22` build-ready героя, а browser E2E не показал measured render bottleneck. Поэтому виртуализация списка намеренно не добавлена без runtime evidence; решение пересматривается по результатам production/native измерений выше.

## Ветки героев

### BL-002 — Добавить учёт собственных ресурсов

Возможное расширение калькулятора `Ветки героев` добавляет секцию `Мои ресурсы`, не создавая новую самостоятельную функцию или spec. До реализации необходимо подтвердить полный каталог ресурсов, IDs и содержимое сундуков.

Предварительно подтверждены возможные источники очков веры:

- большой персональный сундук божественности — `600` очков веры;
- малый сундук божественности — количество и ID предстоит подтвердить;
- персональный сундук развития героя — `50` очков выбранного вида веры;
- персональный сундук веры — `300` очков выбранного вида веры.

Текущий контракт калькулятора заканчивается стабильным результатом `requiredResources`. Расширение должно вычислять отдельный `remainingResources`, не менять исходную сумму требуемых ресурсов, дерево, выбор пути или базовую модель стоимости.
