# «Мои ресурсы» в калькуляторе божественности

## Контекст

Экран божественности уже рассчитывает полный расход самоцветов уровней 1–7 для выбранного диапазона и прогресса. В игровых данных проекта также есть два персонализированных сундука:

- `600001` — варианты награды для самоцветов уровней 1–5;
- `600076` — варианты награды для самоцветов уровней 1–7.

Каждый сундук выдаёт один фиксированный набор самоцветов выбранного уровня, а не все перечисленные варианты одновременно. Пользователь сам указывает количество имеющихся сундуков и отдельных самоцветов; калькулятор не подбирает количество сундуков за пользователя.

## Цель

Добавить над карточкой «Расход ресурсов» сворачиваемый блок «Мои ресурсы». Выбранные в нём сундуки и отдельные самоцветы уменьшают отображаемый остаток ресурсов для прокачки.

## UI

В закрытом состоянии отображается только кнопка-заголовок «Мои ресурсы» с индикатором раскрытия. Индикатор повторяет существующий проектный паттерн `HeroGuideSelector`: `▾` в закрытом состоянии и `▴` в открытом, внутри одинакового фиксированного контейнера. Символы `⌄` и `⌃` не используются.

В раскрытом состоянии блок содержит:

1. Две строки сундуков:
   - малый сундук `600001` для уровней 1–5;
   - большой сундук `600076`, в первую очередь для уровней 6–7.
2. В каждой строке слева располагается компактная группа в порядке: кнопка уменьшения, игровая PNG-иконка с короткой подписью, кнопка увеличения. Между тремя элементами сохраняются одинаковые заметные отступы, чтобы кнопки не сливались с иконкой. Числовой счётчик отделён от группы и прижат к правому краю строки.
3. Семь строк отдельных самоцветов уровней 1–7 с теми же элементами управления и игровыми PNG-иконками.
4. Кнопку «Сбросить мои ресурсы», которая обнуляет только счётчики сундуков и самоцветов.

Для самоцветов используется такая же компоновка: `−`, игровая иконка с уровнем, `+` образуют левую группу, а счётчик остаётся справа. Иконка с подписью больше не растягивается на всё свободное пространство между кнопками; свободное место отделяет левую группу от счётчика.

Счётчики принимают только целые неотрицательные значения. Кнопка уменьшения не меняет нулевое значение. Сворачивание блока не отключает и не очищает выбранные ресурсы.

Существующая кнопка «Сбросить прогресс» продолжает сбрасывать только диапазон и прогресс прокачки.

## Расчёт остатка

Входные данные:

- исходный `StoneCosts`, рассчитанный существующей функцией для выбранного прогресса;
- количество отдельных самоцветов уровней 1–7;
- количество сундуков `600001` и `600076`.

Расчёт выполняется детерминированно в следующем порядке:

1. Из каждого уровня напрямую вычитаются отдельные самоцветы этого уровня.
2. Сундуки `600001` распределяются по уровням 1–5, начиная с самого низкого уровня, у которого остался дефицит.
3. Один сундук применяется только к одному уровню и уменьшает дефицит на фиксированную награду этого уровня. Излишек не переносится на другой уровень.
4. Сундуки `600076` сначала распределяются по уровням 6–7, также начиная с самого низкого незакрытого уровня.
5. Если после расходования малых сундуков остался дефицит уровней 1–5, оставшиеся большие сундуки могут закрывать его, начиная с уровня 1.
6. Значение остатка на каждом уровне ограничивается снизу нулём.
7. Если дефицит всех доступных уровней закрыт, лишние добавленные сундуки сохраняются в счётчике, но не меняют результат.

Таким образом, фиксированная награда сундука может перекрыть потребность с избытком. Недостаточное количество сундуков оставляет ненулевой остаток.

## Архитектура

Расчёт остатка оформляется чистой функцией в модели `features/divinity`. Она получает исходную стоимость и состояние ресурсов, использует существующий каталог `divinityGemChests` как источник фиксированных наград и возвращает новый `StoneCosts`, не изменяя входные объекты.

Состояние ресурсов отделяется от состояния прогресса:

- отдельный тип для количества двух сундуков и семи уровней самоцветов;
- отдельный hook для загрузки и изменения счётчиков;
- отдельный ключ AsyncStorage и отдельная операция сброса.

Это сохраняет независимость существующего расчёта прогресса и позволяет двум кнопкам сброса выполнять разные задачи. Состояние ресурсов сохраняется после перезагрузки страницы по той же схеме, что и текущий прогресс.

UI получает исходный расход, состояние ресурсов и обработчики изменения. Карточка «Расход ресурсов» отображает уже рассчитанный остаток. Существующие интерфейсы `GemIcon` и каталог сундуков переиспользуются; новые копии игровых данных или изображений не создаются.

## Проверка

Функциональные тесты должны подтвердить:

- нулевые ресурсы не меняют исходный расход;
- отдельные самоцветы вычитаются только из соответствующего уровня и не дают отрицательных значений;
- малые сундуки закрывают уровни 1–5 в порядке от низкого к высокому;
- фиксированный избыток одного набора не переносится на следующий уровень;
- большие сундуки сначала закрывают уровни 6 и 7;
- после исчерпания малых сундуков большие могут закрывать оставшиеся уровни 1–5;
- лишние сундуки не создают отрицательный остаток;
- состояние корректно загружается, сохраняется и сбрасывается независимо от прогресса.

После реализации необходимо запустить все тесты, TypeScript-проверку и web-сборку. На `localhost` визуально проверяются раскрытие и сворачивание, обе игровые иконки сундуков, семь игровых иконок самоцветов, работа кнопок и отсутствие битых путей к изображениям.

## Вне области задачи

- автоматический расчёт рекомендуемого количества сундуков;
- ручное назначение каждого сундука конкретному уровню;
- использование сундуков `600031` и `600077` или учёт Веры;
- изменение данных стоимости прокачки и существующего интерфейса выбора прогресса.
